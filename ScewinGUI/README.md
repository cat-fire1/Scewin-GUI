# Scewin GUI

**Версия 4.0.0:** [скачать ZIP для Windows x64](https://github.com/cat-fire1/Scewin-GUI/releases/latest/download/ScewinGUI-windows-x64.zip) · [описание релиза](https://github.com/cat-fire1/Scewin-GUI/releases/tag/v4.0.0).

Распакуйте архив целиком и запустите `ScewinGUI/ScewinGUI.exe`. Папку `_internal` и vendor-файлы оставьте рядом с EXE. Устанавливать Python и Node.js для готовой сборки не нужно; необходим WebView2 Runtime.

Десктопный редактор NVRAM для Windows. Интерфейс перенесён на **React + TypeScript + CSS**, окно приложения работает через **pywebview / WebView2**. Парсер, валидация, атомарное сохранение и операции SCEWIN остаются на Python.

Сохранены тёмная тема Fluent, боковая навигация, редактор с таблицей, бэкапы, документация и языки RU / UK / EN. Таблица отрисовывает только видимые строки. Стили и компоненты можно менять независимо от BIOS-логики.

## Запуск из исходников

Нужны Python 3.11+, Node.js 22.12+ и установленный Microsoft Edge WebView2 Runtime. На этой машине проверено с Python 3.14 и WebView2. Для редактирования файлов права администратора не нужны; для операций SCEWIN запускайте терминал от администратора.

Из корня проекта:

```powershell
python -m pip install -r requirements.txt
npm ci --prefix frontend
npm run build --prefix frontend
python main.py
```

После сборки интерфейса обычный запуск требует только `python main.py`: Node.js и сервер разработки при этом не используются. Старый `main.exe` в корне относится к предыдущей Qt-версии.

## Разработка с автоматическим обновлением

Первый терминал:

```powershell
npm run dev --prefix frontend
```

Второй терминал:

```powershell
python main.py --dev
```

Изменения React и CSS появляются в окне автоматически. Изменения Python требуют перезапуска приложения. Сервер разработки слушает только `127.0.0.1:5173`. Флаг `--debug` открывает инструменты разработчика для обычной собранной версии.

## Где менять интерфейс

| Задача | Файл |
| --- | --- |
| Цвета, шрифты, скругления, размеры, высота строк | `frontend/src/styles/theme.css` |
| Расположение и оформление элементов | `frontend/src/styles/app.css` |
| Навигация | `frontend/src/components/Sidebar.tsx` |
| Экран редактора и его кнопки | `frontend/src/pages/Editor.tsx` |
| Таблица, редакторы ячеек, фильтры и сортировка | `frontend/src/components/SettingsTable.tsx` |
| Экран бэкапов | `frontend/src/pages/Backups.tsx` |
| О программе и документация | `frontend/src/pages/About.tsx` |
| Состояние приложения и сообщения | `frontend/src/App.tsx` |
| Типы данных и вызовы Python | `frontend/src/types.ts`, `frontend/src/api.ts` |
| Тексты | `scewin_gui/translations/{ru,uk,en}.json`, `desktop_{ru,uk,en}.json` |
| Python API интерфейса | `scewin_gui/desktop_api.py` |
| Окно, запуск и защита от второго экземпляра | `scewin_gui/desktop.py` |

Например, для изменения акцента, отступов и плотности таблицы:

```css
:root {
  --color-accent: #76b9ed;
  --page-padding: 30px;
  --row-height: 42px;
}
```

Компоненты используют обычный CSS без обязательной библиотеки оформления. При изменении высоты строк виртуализация таблицы считывает `--row-height` из темы. Python остаётся источником истины для значений: он проверяет числа, идентификаторы вариантов и принадлежность изменения текущему документу.

Старые файлы Qt в `scewin_gui/ui_*.py`, `app.py`, `main_window.py`, `nvram_table.py`, `qt_compat.py` и `workers.py` оставлены как справочная реализация. Новый запуск их не импортирует и не требует установки Qt.

## Работа с файлами

- **Открыть файл** загружает `.txt` / `.nvram`. Поиск работает по имени, описанию, токену и смещению.
- **Применить** сохраняет только изменённые блоки в `nvram_new.txt`, как в прежней версии. Эта кнопка не записывает BIOS.
- **Сохранить как…** сохраняет полный документ в выбранный файл и открывает его как текущий. Перезапись `nvram.txt` этим действием запрещена: он используется для защитного бэкапа.
- **Импорт файла** записывает текущий открытый файл с диска. **Импорт** записывает `nvram_new.txt`. Перед записью показывается подтверждение с путём к файлу.
- **Экспорт** читает BIOS в `nvram.txt`, открывает его и создаёт бэкап.
- **Создать бэкап** копирует текущий экспорт `nvram.txt`; **Восстановить** записывает выбранный бэкап в BIOS.

При старте существующий `nvram.txt` загружается автоматически. Если его нет, приложение ждёт открытия файла или явного нажатия «Экспорт». Запуск приложения сам по себе не запускает SCEWIN.

Сочетания клавиш: `Ctrl+F` — поиск, `Esc` — очистить поиск / отменить ввод числа, `Enter` — завершить ввод числа, `Ctrl+S` — применить изменения, `Ctrl+Shift+S` — сохранить полный файл. Стрелки вверх/вниз выбирают параметры, когда фокус на таблице. Заголовки столбцов переключают сортировку, заголовок «Значение» возвращает порядок файла.

BIOS-операции выполняются последовательно. Проверки целостности vendor-файлов, подтверждение записи и обязательный защитный бэкап выполняются в Python. Во время операции закрытие окна блокируется. Не храните реальные BIOS-дампы в Git.

## Проверки

```powershell
npm run build --prefix frontend
python -m unittest discover -s tests -v
python tests/smoke_desktop.py
```

Последняя команда открывает настоящее окно WebView2 и проверяет синтетический файл из 2400 параметров: загрузку, числовые значения и варианты с одинаковыми названиями, частичное и полное сохранение, виртуализацию, поиск, фильтрацию регистров, языки и страницы приложения. Файловые диалоги в этом сценарии заменены предсказуемыми путями во временной папке. Все vendor-вызовы заблокированы. При наличии Pillow снимок окна сохраняется в `artifacts/desktop-smoke.png`.

Реальные операции записи BIOS этими проверками не выполняются.

## Сборка EXE

```powershell
python -m pip install pyinstaller
.\build.ps1
```

Результат: `dist/ScewinGUI/ScewinGUI.exe`. Распространяйте всю папку `dist/ScewinGUI`, включая `_internal` и vendor-файлы. Node.js и установленный Python пользователю сборки не нужны; WebView2 Runtime должен присутствовать в Windows. Локальные настройки, дампы, логи и бэкапы не включаются в сборку. Для повторной сборки без `npm ci`: `.\build.ps1 -SkipInstall`.

Если в папке предыдущей сборки уже есть дампы, настройки или бэкапы, скрипт не перезапишет её. Выберите отдельный каталог:

```powershell
.\build.ps1 -DistPath artifacts/release-build
.\package-release.ps1 -BundlePath artifacts/release-build/ScewinGUI
```

Архив и контрольная сумма появятся в `releases/v4.0.0/`. В ZIP входят только EXE, vendor-файлы, `_internal`, лицензия и инструкция; пользовательские дампы и бэкапы не добавляются.
